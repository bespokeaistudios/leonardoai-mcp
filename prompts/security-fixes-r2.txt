## Fix 7: Add AbortController-based fetch timeout to all outbound HTTP calls

In src/leonardo-client.ts:

1. Add constant at the top of the class/export area:
   ```
   const DEFAULT_FETCH_TIMEOUT_MS = 30_000;
   ```

2. In BOTH `request()` and `v2Request()` methods, wrap the fetch call:
   ```
   const controller = new AbortController();
   const timeoutId = setTimeout(() => controller.abort(), DEFAULT_FETCH_TIMEOUT_MS);
   try {
     const response = await this.fetchImpl(url, { ...init, signal: controller.signal });
     // ... existing response handling code ...
   } finally {
     clearTimeout(timeoutId);
   }
   ```
   
3. If fetch is aborted (signal aborted), catch it and throw a clear error:
   ```
   if (controller.signal.aborted) {
     throw new Error(`Leonardo API request timed out after ${DEFAULT_FETCH_TIMEOUT_MS / 1000}s`);
   }
   ```
   Handle this before the `if (!response.ok)` check.

4. In tests/leonardo-client.test.ts, add a test:
   - Mock fetch to return a promise that never resolves (hangs)
   - Call a client method that uses request() (e.g., listModels)
   - Verify the promise rejects with a timeout error within 35 seconds
   - Use vitest fake timers OR a short timeout value for the test
